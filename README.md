# Monitoring-Lab7
Лабораторна робота №7: Моніторинг брокера повідомлень RabbitMQ і NoSQL-баз даних

Цей репозиторій містить матеріали, конфігураційні файли та автоматизований діагностичний модуль для виконання лабораторної роботи з дисципліни «Моніторинг та аналіз даних у production-середовищах».

📌 Опис проекту

Метою роботи є дослідження продуктивності, аналіз телеметрії та виявлення типових аномалій у роботі компонентів черг повідомлень і NoSQL-сховищ у розподіленій мікросервісній архітектурі.

Досліджуваний стек:

RabbitMQ 3.13 (з плагіном Management) — моніторинг черг, облік швидкостей надходження/доставки (publish/deliver/ack), виявлення завислих повідомлень (unacked), аналіз лімітів пам'яті (high watermark).

MongoDB 7.0 — системне профілювання запитів (system.profile), ідентифікація повільних операцій, детекція неефективних планів вибірки (COLLSCAN замість індексного перегляду) та статистика колекцій (collStats).

Redis 7.2 — діагностика споживання оперативної пам'яті, коефіцієнта фрагментації (mem_fragmentation_ratio), кількості клієнтських підключень та виявлення блокуючих операцій лінійної складності через механізм SLOWLOG.

🚀 Швидкий старт

1. Попередні вимоги

Встановлений Docker Desktop (з підтримкою Docker Compose v2).

Інтерпретатор Python 3.10+ з менеджером пакетів pip.

2. Запуск інфраструктури в контейнерах

У кореневій директорії проекту виконайте команду для завантаження образів та підняття сервісів в ізольованій мережі:

docker compose up -d


Перевірити статус запущених контейнерів:

docker compose ps


Повинні успішно працювати три контейнери:

lab7-rabbitmq (порти 5672, 15672)

lab7-mongodb (порт 27017)

lab7-redis (порт 6379)

3. Встановлення залежностей Python

Для взаємодії з сервісами встановіть необхідні клієнтські драйвери:

pip install -r requirements.txt


(Або вручну: pip install pika pymongo redis)

⚙️ Емуляція навантаження та діагностика

Для симуляції виробничого навантаження, наповнення баз даних та провокування аномалій запустіть тестовий модуль:

python generate_load_and_diagnose.py


(У Windows PowerShell також доступна команда: py generate_load_and_diagnose.py)

Що виконує скрипт:

RabbitMQ:

Створює персистентну чергу orders.

Відправляє пачку з 200 повідомлень.

Консьюмер підтверджує 50 повідомлень (ACK) і навмисно залишає 10 повідомлень у статусі доставлених без підтвердження (unacked), що симулює зависання воркера через обмеження попередньої вибірки (prefetch_count).

MongoDB:

Активує системний профілювальник операцій 1-го рівня для всіх викликів тривалістю понад 10 мс (slowms=10).

Наповнює колекцію users 15 000 документів.

Виконує неіндексований пошук за регулярним виразом, провокуючи план повного перебору колекції COLLSCAN.

Зчитує топ повільних запитів із колекції system.profile та метрики обсягу пам'яті через collStats.

Redis:

Записує 10 000 ключів із встановленим строком життя (TTL = 3600s) через оптимізований конвеєр pipeline.

Запускає ресурсомістку блокуючу команду KEYS cache:key:*.

Зчитує звіт INFO (використана пам'ять, пік, коефіцієнт фрагментації) та виводить останні записи з журналу SLOWLOG.

📊 Веб-інтерфейси та моніторинг

RabbitMQ Management UI

URL: http://localhost:15672

Логін: guest

Пароль: guest

Основні екрани для перевірки:

Overview: графіки черг Queued messages (Ready, Unacked, Total), інтенсивність операцій Message rates, стан апаратних ресурсів вузла Nodes (Memory High Watermark).

Queues and Streams: таблиця активних черг з перевіркою параметрів збереження стану (Durable) та лічильників повідомлень.

MongoDB CLI (опціонально)

Підключення до інтерактивної оболонки бази даних усередині контейнера:

docker exec -it lab7-mongodb mongosh


Перегляд повільних запитів:

use monitoring_db
db.system.profile.find().pretty()


Redis CLI (опціонально)

Підключення до термінала Redis:

docker exec -it lab7-redis redis-cli


Перегляд повільних команд та метрик пам'яті:

SLOWLOG GET 10
INFO memory


🛑 Зупинка середовища

Для повної зупинки комплексу контейнерів виконайте:

docker compose down


Якщо необхідно також очистити створені томи даних:

docker compose down -v
